# Overview
This minimal example shows the proposed stocastic self-consistent harmonic approximation (SSCHA) workflow on a palladium hydride (PdH) compound.

Our main goal is to optimize, ideally GPU accelerate, two core components of the open-source SSCHA package (https://sscha.eu/) that we are using for this workflow. This package is openly developed on Github (https://github.com/SSCHAcode/python-sscha) and is currently a mix of partially MPI parallelized Python, partially openMP parallelized Fortran, and Julia code.

For a detailed description of the method and the mathematics I recommend this review paper: https://iopscience.iop.org/article/10.1088/1361-648X/ac066b

## Simplified description

- At the center of this method is a gradient based minimization of a very high-dimensional stochastic target function, the free energy.
- The SSCHA main loop (Free energy minimization)
    1. samples the target function and the corresponding gradient using an ensemble, i.e., evaluates the ML potential for every sample in the ensemble.
    2. performs gradient descent for several iterations by updating the free energy and its gradient using importance sampling to avoid evaluation of the full ensemble every step.
    3. whenever the optimization moves too far from the last fully sampled point, as measured by the Kong-Lui effective sample size, a new ensemble is generated (Step 1)
- After convergence, determined by the ratio of the gradient to the estimated gradient error, the second derivative with respect to the atomic coordinates (the positional free energy Hessian) is evaluated.

## Goal

- Historically, the sampling in step 1 dominiated the computational effort compared to the gradient descent and importance sampling. However, using modern (GPU-accelerated) ML potentials more than half of the time is spend in this part of the main loop.
- For our screening studies, there are two computational bottlenecks that we would like to optimize. Ideally, a GPU implementation of these components would allow us to run the full workflow on a GPU cluster.
    - Estimation of the free energy gradient using importance sampling (`Ensemble.get_preconditioned_gradient()`). 
    - Evaluation of the free energy Hessian (`Ensemble.get_free_energy_hessian()` more specifically the Fortran function `SCHAModules.get_v3`).
# PdH Example
In this simplified example the two components can be tested/benchmarked/optimized independently. My naive guess is that the `free_energy_hessian` would be the simpler initial target.

## Installation / Setup
For both components:
- Install the `sscha` code following https://github.com/SSCHAcode/python-sscha#easy-installation-through-anacondamamba

Only required for the free energy minimization:
- Install the `nequip` ML potential library https://nequip.readthedocs.io/en/latest/guide/getting-started/install.html
- Download and compile the NequIP-OAM-XL foundation model https://nequip.readthedocs.io/en/latest/guide/getting-started/workflow.html#compiling-models-from-nequip-net
- Optional, I used the `openequivariance` GPU kernel generator to accelerate the NequIP potential and reduce the GPU memory footprint of the model https://nequip.readthedocs.io/en/latest/guide/accelerations/openequivariance.html

## Running the examples
- `sscha/run_sscha.py`: reads the harmonic dynamical matrices (`4x4x4_harmonic_dyn*`) and performs the main SSCHA loop, i.e., the free energy minimization.
- `hessian/free_energy_hessian.py`: reconstructs the final ensemble of the free energy minimization and evaluates the free energy Hessian.

## Appendix
For the sake of completeness: The folder `harmonic` contains the two scripts used to generate the initial dynamical matrix.
- The input to the workflow was generated by first relaxing an initial structure `PdH.cif` while fixing the symmetry `python relax_geometry.py` 
- Using the relaxed structure `PdH_relaxed.cif` the harmonic phonons were calculated using a finite difference approach `python phonons_harmonic.py`
